## 3. 为什么 `mini-gratitude` 足够小但覆盖完整

`mini-gratitude` 的业务非常小，但它天然触发全部工程问题：

| 业务点 | 触发工厂能力 |
|---|---|
| 感恩日记 | 隐私策略、local_only、Privacy Gateway 思维 |
| CLI | TDD、测试、项目脚手架 |
| SQLite | ADR、架构设计、数据生命周期 |
| export | 安全审查、格式测试、bug 修复 |
| list --date | 功能迭代、SPEC/TASK_GRAPH 更新 |
| gratitude journaling 外部资料 | 联网 Search / Extract / RAG / citations |
| 是否加 AI 鼓励语 | 多专家评审、范围控制 |
| 项目完成 | RETRO、lesson、交接 |

因此不需要做大项目，也能覆盖全工厂。

## 4. 当前无法或不应在演示项目中真实触发的能力

以下能力不建议在教学项目中做高风险真实操作，但已经通过安全方式覆盖：

| 能力 | 为什么不真实触发 | 替代覆盖方式 |
|---|---|---|
| 私域 Chrome DevTools 登录态 | 涉及用户 cookie / session | 手册说明 private mode 边界，示例不使用私域数据 |
| 高危 MCP 写操作 | 需要人工审批，教学项目无必要 | 手册解释 MCP Guard 与 PreToolUse，示例使用 research mode |
| 真实 CAPTCHA 对抗 | 不应绕过网站访问控制 | 诊断脚本识别并 circuit-break |
| 生产发布 | 当前工厂是本地开发体系 | 使用治理检查 + 交接 + release 准备覆盖 |

这些不是遗漏，而是安全边界设计。

## 5. 最终验收标准

一个新用户完成手册和示例后，应能：

- 独立创建项目。
- 独立完成五阶段。
- 使用 forge CLI。
- 使用 Network CLI。
- 正确保存 API key 到 `.env`。
- 理解搜索 fallback 和 snippet fallback。
- 写 ADR、TASK_GRAPH、BUILD_LOG、RETRO。
- 调用合适 Agent / Skill。
- 跑测试和治理检查。
- 修 bug、做迭代、交接项目。
- 不泄露密钥和私域数据。

如以上全部满足，则工厂教学覆盖验收通过。
