## 1. FORGE Factory 是什么

FORGE Factory 是一个 **AI 项目孵化工厂**。它不是单一 App，也不是单纯脚手架，而是一套把“模糊想法”变成“可运行、可测试、可交接 AI 软件项目”的工程体系。

它把项目开发拆成五个阶段：

```text
DISCOVERY → SPEC → BUILD → HARDEN → RETRO
```

每个阶段都有：

- 明确输入
- 明确产物
- 明确 Agent / Skill
- 明确人工确认点（HITL Gate）
- 明确文档记录
- 明确测试与交接要求

### 1.1 工厂设计思想

| 思想 | 含义 |
|---|---|
| Local First | 优先本地运行、开源组件、可离线维护。 |
| HITL | 关键需求、架构、安全和知识入库必须人工确认。 |
| 文档即控制面 | `HANDOFF`、`PROJECT_STATE`、`TASK_BACKLOG`、`DEV_LOG`、`CHANGELOG` 是可接手性的核心。 |
| 配置驱动 | 模型、路由、隐私、联网、安全策略都尽量通过 YAML / 配置管理。 |
| 安全先行 | Privacy Gateway、MCP Guard、Canary、PII 检测、模式隔离都是默认边界。 |
| 可复用资产沉淀 | RETRO 后把经验沉淀到 `_factory/lessons`、`skills`、`patterns`。 |
| 小步可验证 | 每轮改动必须跑测试、更新文档、提交可工作的仓库状态。 |

## 4. 五阶段生命周期

| 阶段 | 目标 | 主要产物 | 推荐 Agent / Skill | Gate |
|---|---|---|---|---|
| DISCOVERY | 澄清需求、用户、边界、验收标准 | `docs/DISCOVERY.md` | discovery-interview | GATE-1 |
| SPEC | 架构设计、任务拆解、风险识别 | `SPEC.md`、`TASK_GRAPH.md`、`RISK.md`、ADR | arch-advisor、arch-design | GATE-2 / GATE-3 |
| BUILD | TDD 开发、持续测试、记录变更 | 代码、测试、`BUILD_LOG.md` | coder、reviewer、tdd-cycle | 阶段内测试门禁 |
| HARDEN | 安全、隐私、性能、异常场景 | `SECURITY_REVIEW.md` | security-reviewer | GATE-4 |
| RETRO | 复盘、提炼可复用资产 | `RETRO.md`、lesson/skill/pattern | retro-analyst | GATE-5 |

### 4.1 HITL Gate 原则

- GATE-1：需求边界人工确认。
- GATE-2：架构与技术路线人工确认。
- GATE-3：风险和合规人工确认。
- GATE-4：最终验收人工确认。
- GATE-5：知识入库人工确认，防止污染工厂知识库。

真实密钥不要提交。做法：

```bash

chmod 600 .env
```

编辑 `.env`：

```bash
TAVILY_API_KEY="tvly-..."
```

代码会自动加载：

1. 当前 shell 已 export 的变量；
2. 项目根 `.env`；
3. `_infra/.env`。

`.env` 不覆盖已 export 的变量。

验证：


## 6A. Claude Code for VS Code：日常主使用方式

虽然工厂提供了终端 CLI，但日常开发项目时，推荐主入口是 **Claude Code for VS Code 的自然语言对话界面**。CLI 更多用于验证、自动化、测试、健康检查和可重复操作。

### 6A.1 使用模型

```text
你在 VS Code 中对 Claude Code 说自然语言
  ↓
Claude Code 读取全局 CLAUDE.md / 项目 AGENTS.md / 当前 Skill
  ↓
根据阶段调用工具、编辑文件、运行测试
  ↓
必要时通过本地 LiteLLM / Smart Proxy / Ollama / MTPLX 调用本地开源模型
  ↓
人类确认 Gate / 高风险动作
```

### 6A.2 一次性准备

1. 复制全局模板：

```bash
mkdir -p ~/.claude
cp _infra/CLAUDE.global.md ~/.claude/CLAUDE.md
```

2. 在项目根目录准备本地 `.env`：

```bash
cp .env.example .env
chmod 600 .env
# 填入 TAVILY_API_KEY / SERPER_API_KEY / PII_MAP_ENCRYPTION_KEY 等
```

3. 启动本地服务：

```bash
bash scripts/forge-start.sh
```

4. 如使用 OpenAI-compatible 本地网关，在启动 Claude Code 的终端设置：

```bash
export OPENAI_BASE_URL=http://localhost:4000/v1
export OPENAI_API_KEY=sk-forge-local-anytoken
```

### 6A.3 在 VS Code 中打开工厂

推荐方式：直接从 VS Code 菜单打开项目目录：

```text
File → Open Folder... → ~/MusicProject/AI-Project-Incubation-Factory
```

如果你已经在 VS Code 中安装了 shell command，才可以在终端运行：

```bash
code ~/MusicProject/AI-Project-Incubation-Factory
```

如果终端提示 `zsh: command not found: code`，请在 VS Code 命令面板（`Cmd + Shift + P`）运行：

```text
Shell Command: Install 'code' command in PATH
```

这不是工厂故障，只是 VS Code 的 shell command 未安装。

在 VS Code 中打开 Claude Code 面板。注意：**这里说的是 Claude Code 对话框，不是 VS Code 内置终端**。

本地开源模型做长工具链规划时，建议不要一上来让模型“自己去读取很多文件”。更稳的方式是用 Claude Code 的 `@文件` 上下文附加能力，把关键文件直接附加到对话中。

第一句话建议使用纯文本文件名，避免 Markdown 链接：

```text
你现在是 FORGE Factory Orchestrator。
请基于 @HANDOFF.md @docs/PROJECT_STATE.md @TASK_BACKLOG.md @docs/工厂使用手册.md 的内容，告诉我当前项目状态、当前阶段、下一步建议做什么。
要求：先只总结，不要修改文件，不要运行命令。
```

如果你的 Claude Code 版本不支持 `@文件`，请改成分步读取：

```text
请先只读取并总结 HANDOFF.md。不要读取其它文件，不要修改文件。
```

等它返回后再继续：

```text
继续读取 docs/PROJECT_STATE.md 并总结与 HANDOFF.md 的一致/不一致。
```

### 6A.4 按阶段对话，而不是只敲命令

DISCOVERY：

```text
我要创建一个新项目。请作为 Orchestrator 加载 discovery-interview skill，对我做结构化访谈，并生成 DISCOVERY.md 草稿。过程中需要我确认的问题一次性列出。
```

SPEC：

```text
请切换为 arch-advisor 角色，基于 DISCOVERY.md 产出 SPEC、TASK_GRAPH、RISK 和必要 ADR。禁止开始编码，先等我过 GATE-2。
```

BUILD：

```text
请按 TASK_GRAPH 的下一个 ready task 执行。严格 TDD：先写测试，再实现，再跑测试，再更新 BUILD_LOG 和 TASK_GRAPH。
```

HARDEN：

```text
请切换 security-reviewer，执行威胁建模、隐私检查、依赖检查、高风险动作审查，产出 SECURITY_REVIEW.md。
```

RETRO：

```text
请切换 retro-analyst，生成 RETRO.md，并提出可入库 lesson/skill/pattern 候选。等我确认 GATE-5 后再写入 _factory。
```

### 6A.5 Claude Code 模式切换

Claude Code 不是每个会话都应该拥有所有工具。使用前按任务选择：

```bash
scripts/switch-mode.sh coding   # 写代码 / 跑测试
scripts/switch-mode.sh research # 公开搜索 / 抓取 / RAG
scripts/switch-mode.sh private  # 私域只读 profile，需人工控制
```

推荐会话拆分：

| 工作 | 推荐模式 | 说明 |
|---|---|---|
| 写代码 | coding | 不给浏览器和私域能力。 |
| 联网研究 | research | 可用 SearXNG/Crawl4AI/Playwright public。 |
| 私域页面读取 | private | 仅 Chrome DevTools private，禁止 cookie/storage。 |
| 高风险动作 | 单独会话 + 人工确认 | 不与 coding/research 混用。 |

### 6A.6 高风险动作在 Claude Code 中怎么做

高风险动作包括：删除、提交、push、浏览器点击提交、截图、私域读取、MCP schema 变化、疑似 cookie/session/storage 访问等。

标准提示词：

```text
这是高风险演示。请先列出：动作、影响范围、回滚方式、需要我人工确认的点。没有我的明确“yes”不得执行。
```

如果 Hook / MCP Guard 返回 deny，不要绕过，应该读取 reason 并修正方案。

### 6A.7 CLI 与 VS Code 对话如何配合

- VS Code 自然语言负责“理解、规划、编辑、解释”。
- CLI 负责“可重复验证”。
- 每次 Claude Code 改完后，要求它运行：

```bash
make docs-check
python3 -m pytest _infra/network/tests/unit/ _infra/network/tests/security/ -q
```

### 6A.8 VS Code `settings.json` 推荐配置

Claude Code for VS Code 接本地开源模型时，应让 Claude Code 走本地 Anthropic-compatible 智能代理 `http://localhost:4000`。注意这里 **不要加 `/v1`**，因为 Claude Code 会自己请求 `/v1/messages`。

推荐配置片段：

```json
{
  "claudeCode.preferredLocation": "panel",
  "claudeCode.disableLoginPrompt": true,
  "claudeCode.environmentVariables": [
    { "name": "ANTHROPIC_BASE_URL", "value": "http://localhost:4000" },
    { "name": "ANTHROPIC_API_KEY", "value": "sk-forge-local-anytoken" },
    { "name": "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC", "value": "1" },
    { "name": "API_TIMEOUT_MS", "value": "3000000" },
    { "name": "FORGE_CLAUDE_CODE_MAX_TOKENS", "value": "1024" }
  ]
}
```

如果 VS Code 报：

```text
There's an issue with the selected model (claude-opus-...). It may not exist or you may not have access to it.
```

优先检查：

1. `scripts/forge-start.sh` 是否已经启动本地 4000 代理；
2. VS Code 是否重启或重新加载窗口；
3. `ANTHROPIC_BASE_URL` 是否是 `http://localhost:4000`；
4. 当前选中的 Claude Code 模型 alias 是否被本地代理映射；
5. 如果本地模型响应过慢，可设置 `FORGE_CLAUDE_CODE_MAX_TOKENS=512` 或 `1024` 后重启 `scripts/forge-start.sh`。

当前 Claude Code for VS Code UI 里常见选项与本地映射关系如下：

| VS Code 选项 | 可能请求的 model alias | 本地实际路由 |
|---|---|---|
| Default / Opus 4.8 (1M context) | `claude-opus-4-8`, `claude-opus-4-8-1m` | `mtplx-qwen36-27b` |
| Sonnet 4.6 | `claude-sonnet-4-6` | `mtplx-qwen36-27b` |
| Sonnet 4.6 (1M context) | `claude-sonnet-4-6-1m` | `mtplx-qwen36-27b` |
| Haiku 4.5 | `claude-haiku-4-5` | `mtplx-qwen36-27b` |

```text
claude-opus-4-8
claude-opus-4-8-1m
claude-opus-4-1
claude-opus-4-1-20250805
claude-opus-4-20250514
claude-sonnet-4-20250514
```

如果 `curl http://localhost:4000/v1/messages` 返回 `{"detail":"Not Found"}`，通常不是模型 alias 问题，而是 4000 端口被旧的 `smart_proxy_streaming.py` 或其他服务占用。请重新运行最新 `scripts/forge-start.sh`，它会按端口清理 4000/4001 后再启动正确的 `smart_proxy.py`。

如果 streaming curl 只有 `message_start/message_stop`，没有 `content_block_delta`，说明代理没有把后端完整 JSON 包装为 Anthropic SSE。当前 `smart_proxy.py` 已修复：Claude Code streaming 路径对本地后端使用非流式 JSON，再包装为 Anthropic SSE 文本增量。

### 6A.9 本地模型 + Claude Code 工具调用排障

如果在 Claude Code 面板里输入“请读取 HANDOFF.md ...”后，它只回复“我来读取文件”，然后长时间不动，通常有三类原因：

1. **你把 VS Code 命令当成终端命令执行了**
   - `Developer: Reload Window` 必须在 `Cmd + Shift + P` 命令面板里执行，不是在 zsh 终端里执行。
   - `code .` 只有安装了 VS Code Shell Command 后才可用；没有安装时可直接用 Finder / Dock 打开 VS Code。

2. **本地模型没有稳定地产生 Claude Code 工具调用**
   - 本地开源模型可以聊天和规划，但复杂工具调用不一定像 Claude 官方模型一样稳定。
   - 解决方式：优先用 `@HANDOFF.md` 这类上下文附加，或分步要求它只读一个文件。

3. **一次性上下文太大**
   - 不要第一句话要求读取 4～8 个长文档并制定完整计划。
   - 建议顺序：`HANDOFF.md` → `PROJECT_STATE.md` → `TASK_BACKLOG.md §10` → 当前任务相关文档。

推荐的最小诊断顺序：

```text
只回复 pong
```

若 10 秒内正常，再试：


若仍正常，再试：

### 6A.10 本地模型能力边界与等待时间预期

当前 Claude Code for VS Code 版本：用户已验证 v2.1.193；VS Code 版本：1.126.0。该组合可通过本地 `http://localhost:4000` 代理接入开源模型。

本地开源模型和官方 Claude 的差异：

| 场景 | 推荐方式 | 预期等待 |
|---|---|---|
| `只回复 pong` | 新会话直接问 | 5～15 秒 |
| 简单问答 | 不带大文件上下文 | 10～30 秒 |
| 总结一个短文件 | 使用 `@文件` | 20～60 秒 |
| 总结 `HANDOFF.md` / `PROJECT_STATE.md` | 使用 `@文件`，一次一个 | 1～3 分钟 |
| 一次性读取多个长文档 | 不推荐 | 可能 5～20 分钟或卡住 |
| 让模型自主调用工具读文件 | 谨慎使用 | 本地模型可能不稳定 |
| 编码 + 测试 + 文档同步 | 分 task 执行 | 每步 1～5 分钟 |

`FORGE_CLAUDE_CODE_MAX_TOKENS` 只限制**输出长度**，不减少输入上下文处理时间。建议：

| 用途 | 推荐值 |
|---|---:|
| 快速问答 / 排障 | 256～512 |
| 普通计划 / 小文件总结 | 512～1024 |
| 生成文档草稿 | 1024～2048 |
| 长文档一次性生成 | 不推荐；拆分任务 |

如果输出被截断：

```text
请从上一条被截断处继续，只输出剩余部分。
```

如果模型 3 分钟无任何输出且 GPU 持续高负载，通常仍在推理；如果 5～10 分钟无输出，建议中断并拆小任务。

### 6A.11 如何判断正常工作还是卡死

正常工作信号：

- Activity Monitor 中 GPU / CPU 有负载；
- `/tmp/forge_smart_proxy.log` 出现 `协议转换`；
- 随后出现 `HTTP Request: POST http://127.0.0.1:8080/v1/chat/completions "HTTP/1.1 200 OK"`；
- streaming curl 能看到 `content_block_delta`。

可能卡死信号：

- 5～10 分钟无输出；
- 日志中只有 `协议转换`，长时间没有 200 OK；
- 点击 Stop 后 1～2 分钟 GPU 仍高负载；
- 多个重复请求堆积。

查看状态：

```bash
scripts/model_status.sh
```

停止本地模型和网关，释放显存：

```bash
scripts/stop_local_models.sh
```

连 Ollama 也一起停：

```bash
scripts/stop_local_models.sh --all
```

重新加载：

```bash
bash scripts/forge-start.sh
```

说明：Claude Code 面板的 Stop 按钮只代表客户端停止等待；本地后端请求有时仍会继续跑一段时间。若 GPU 10 分钟不降，请使用 `scripts/stop_local_models.sh`。

### 6A.12 流式输出状态

当前代理已支持 Claude Code Anthropic SSE：

- 如果后端支持 OpenAI SSE，代理会尽量转换为 Anthropic `content_block_delta`。
- 如果后端只返回完整 JSON，代理会把最终文本包装成 Anthropic SSE。此时 VS Code 仍能收到标准事件，但不是 token-by-token 真流式。

用下面命令检查：

```bash
curl -N http://localhost:4000/v1/messages   -H 'content-type: application/json'   -H 'x-api-key: sk-forge-local-anytoken'   -H 'anthropic-version: 2023-06-01'   -d '{
    "model": "claude-opus-4-8-1m",
    "max_tokens": 64,
    "stream": true,
    "messages": [
      {"role": "user", "content": "只回复 pong"}
    ]
  }'
```

必须看到：

```text
event: content_block_delta
```

## 11. 最佳实践

1. 永远小步提交，不做大爆炸重构。
2. 先读 `HANDOFF` 和 `PROJECT_STATE`，再动代码。
3. 任务状态以 `TASK_BACKLOG.md` §10 为准。
4. 架构冲突时先分类：A 已实现且符合、B 疑似废弃、C 部分实现、D 架构冲突、E 无法判断。
5. API key 只放 `.env`，不放代码、不放日志、不发给 Agent。
6. 联网搜索优先 SearXNG，结果不足再 API fallback。
7. 私域数据不进入 Tavily / Serper / Brave。
8. 写操作必须人工确认。
9. 代码改完必须跑测试并更新文档。

## 12. 常见错误与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `loaded tavily api fallback` 没出现 | `.env` 未写或 key 名错误 | 检查 `.env` 和 `load_local_env_files()` 输出。 |
| SearXNG 403 / CAPTCHA | 代理 IP 被风控 | 使用当前健康池，依赖 Tavily/Serper fallback。 |
| `The engine field is missing` | settings.yml partial override 不兼容 | 拉最新代码，已移除 google/brave/startpage override。 |
| `trafilatura extraction timeout` | 目标站点访问慢 | 正常，会 fallback 到 snippet。 |
| Docker healthcheck 触发风控 | healthcheck 查询了默认全引擎 | 当前已固定 `engines=wikipedia`。 |
| Presidio 测试 skipped | 本机未安装 presidio | 可接受；完整环境安装后再跑。 |
| `langgraph` 缺失 | peer-review pattern 依赖未安装 | 安装 `_factory/patterns/peer-review` 依赖。 |
| `.mcp.json` 不是 symlink | 已存在手工文件 | 备份后再用 `scripts/switch-mode.sh`。 |
| Hook deny | mode policy 或参数安全拦截 | 查看返回 JSON reason。 |
