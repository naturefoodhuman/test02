# AI Parenting Copilot家庭私有化 AI 育儿副驾驶系统 PRD

---

## 1. 产品定位

### 1.1 产品名称

**AI Parenting Copilot**  
**家庭私有化 AI 育儿副驾驶系统**

### 1.2 一句话定位

一个部署在家庭本地、以安卓手机为主入口、Mac 常驻服务端为核心、围绕「宝宝当下状态 + 家庭长期记忆」持续运行的 AI 育儿副驾驶。

它帮助父母以极低摩擦完成育儿记录，自动同步家庭照护信息，主动提醒关键事项，保守识别异常趋势，并在关键风险场景下给出可追溯、规则优先的行动建议。

产品本质是：

> **Record（低摩擦记录） × Remember（长期记忆） × Remind / Escalate（主动提醒与升级告警） × Sense（硬件辅助感知）**

### 1.3 设计铁律

当功能、体验、安全、隐私、AI 能力发生冲突时，按以下顺序决策：

> **记录摩擦最低 > 提醒最准时 > 告警必送达 > 预警最保守 > 数据最私有 > 规则不交给 LLM > AI 最克制**

功能优先级排序遵循：

> **高频 > 刚需 > 安全 > 医疗 > 自动化 > 炫技**

### 1.4 产品不是

本产品明确不是：

- 普通育儿知识库
- 问答机器人
- 商业云监控平台
- 医疗诊断系统
- 新生儿生命体征医疗监护设备
- 替代医生的用药决策系统
- 替代父母照护的系统
- 承诺预防 SIDS 的系统
- 全国最佳医院 / 医生推荐系统

医院、科室、医生推荐能力移交独立就医项目，本系统仅保留跳转接口和就诊摘要导出能力。

### 1.5 核心价值

按照真实新生儿家庭的高频痛点排序，本产品核心价值为：

1. **把父母从混乱记录中解放**
   - 喂奶、尿布、睡眠、体温、补剂、用药低摩擦记录。
   - 父母双账号实时同步，不再互相询问“刚刚喂了吗？”。
   - 每条记录明确显示记录人、时间、来源和修改历史。

2. **在正确时间主动提醒**
   - 喂奶提醒、哄睡提醒/唤醒提醒、补剂、疫苗、体检、用药、发育观察点、猛长期预告。
   - 每日晨报合并非紧急事项，减少碎片化打扰。

3. **在异常趋势出现时保守预警**
   - 奶量持续下降。
   - 湿尿布显著减少。
   - 体温达到红线。
   - 睡眠显著碎片化。
   - 黄疸照片趋势加重。
   - 设备离线、同步异常等系统可信度问题。

4. **逐渐理解“我家宝宝”**
   - 形成家庭规则、宝宝行为基线、短期上下文、纠错记忆。
   - 健康类回答自动注入宝宝日龄、体重、近期记录、家庭偏好和过敏史。

5. **睡眠场景辅助感知**
   - 红外摄像头、床区 ROI、毫米波设备、声音与告警链路共同形成辅助感知。
   - 不承诺医疗级生命安全保障。
   - 不使用摄像头判断呼吸频率。

6. **兼顾母亲产后健康**
   - 母亲是核心照护者之一，也是产品用户。
   - 产后泌乳、乳房、情绪、伤口、恶露、复查提醒纳入后续范围。

| 医生 | 不登录 | 仅接收导出 PDF / 就诊摘要 |

### 3.2 宝宝档案必备字段

宝宝档案必须支持以下字段：

- baby_id
- 姓名
- 性别
- 预产期
- 出生日期时间
- 胎龄
- 是否早产
- 出生体重
- 出生身长 / 身高
- 出生头围
- 当前体重
- 喂养方式
- 已知过敏
- 基础病 / 医疗备注
- 疫苗所在地区，默认 CN
- 常用医院 / 儿保机构
- 家庭所在城市

数据结构必须预留多个 baby_id，以支持双胞胎、二孩。

说明：

- 早产 / 低出生体重对发育判断重要。
- 在中国，稳定的早产 / 低体重儿通常仍按出生后实际月龄接种国家免疫规划疫苗，具体由疫苗规则库和医生建议共同约束。

## 5. 摄像头与毫米波硬件接入

### 5.1 摄像头接入

海康威视 DS-2XA8D47F-ISW摄像头：

#### RTSP（负责视频流）

RTSP 是 Frigate / Fregata 等本地 NVR 系统最通用、最高效的拉流标准。支持子码流（低分辨率，专供 M1 Max 的 ANE 做 AI 推理，极大节省算力）。
在NVR 配置文件中，按厂商标准格式组装 RTSP URL 。

#### ISAPI（负责硬件事件上报/控制）

ISAPI（Intelligent Security API）是海康威视的私有 RESTful HTTP 接口。相比 ONVIF，ISAPI 能更深度地调用海康的底层能力。利用摄像头自身的“硬件级移动侦测/人脸比对”等来唤醒 Mac 的 AI 推理（从而让 Mac 平时休眠），用 ISAPI 订阅报警流是最优解。

### 5.2 摄像头布局

| 位置 | 要求 |
|---|---|
| 卧室 | 高位固定覆盖婴儿床，床区清晰 |
| 客厅 | 覆盖游戏垫或日间照护区域 |
| 婴儿床 ROI | 用户手动框定，提升识别准确率 |
| 声音告警 | 摄像头具备双向语音能力 |

### 5.3 视频栈建议

Mac 端视频栈优先：

1. **Fregata**
   - 面向 Apple Silicon。
   - 本地优先。
   - 可利用 Apple Neural Engine / VideoToolbox。
   - 适合 Mac M1 Max 长期运行。

2. **Frigate**
   - 开源本地 NVR。
   - 支持 RTSP。
   - 支持本地 AI 目标检测。
   - 可作为 Docker / NVR 底层方案。

3. **ffmpeg**
   - 用于 RTSP 拉流、抓帧、事件片段切片。

### 5.4 毫米波设备定位

毫米波设备是辅助安心层，用于：

- 存在感
- 呼吸状态
- 心率趋势
- 睡眠分析与提醒
- 离床 / 无人
- 信号丢失
- 与摄像头 / 声音 / 用户输入形成多信号证据

毫米波设备不是医疗设备，不替代成人照护，不承诺预防 SIDS，不单独触发医疗红色告警。

### 5.5 毫米波集成路线（MR60BHA2 + XIAO ESP32C6）

#### 接口协议选择：MQTT (Message Queuing Telemetry Transport)

    原因：MQTT 是物联网数据传输的绝对行业标准。它采用发布/订阅（Pub/Sub）机制，极其轻量、实时性极高、断线重连极其稳定。相比于用 HTTP 不断轮询，MQTT 可以在宝宝呼吸异常的 100 毫秒内，将事件直接推送到 Mac 服务端。

#### 具体实现方式
步骤 A：Mac 端部署 MQTT Broker (核心代理)

在Mac M1 Max 上，运行一个轻量级的 MQTT 代理服务（推荐 Eclipse Mosquitto）：

# Mac 终端通过 Homebrew 安装
brew install mosquitto
# 启动服务（默认监听 1883 端口）
brew services start mosquitto

这样，Mac IP（如 192.168.1.200）就成了整个家庭的物联网数据总线。
步骤 B：ESP32C6 固件开发（数据桥接）

需要通过 Arduino IDE 或 ESPHome 为 XIAO ESP32C6 刷入固件。固件的核心逻辑如下：

    串口读取：通过硬件串口（Serial1）持续读取 MR60BHA2 发来的雷达帧包（雷达协议会输出：体动状态、呼吸率、心率、是否有人等）。
    网络连接：连接到你的家庭 Wi-Fi。
    JSON 组装与 MQTT 发布：将解析后的数据组装成 JSON，通过 PubSubClient 库发布到 Mac 的 MQTT Broker。

MQTT Topic 设计规范（示例）：

    发布主题：baby/radar/telemetry
    Payload (JSON)：

JSON

    {
      "presence": true,
      "state": "sleep",
      "breathing_rate": 35,
      "heart_rate": 120,
      "abnormal_event": "none",
      "timestamp": 1686821400
    }

步骤 C：Mac 服务端（告警编排器）订阅

在 TDD 中定义的 Orchestrator（用 Python 或 Node.js / Kotlin 编写）只需作为 MQTT Client 连接到 Mosquitto，订阅 baby/radar/telemetry，就能以毫秒级延迟拿到体征数据，并送入规则引擎。

#### 联动逻辑（状态机示例）

雷达很敏锐，但容易被风扇、飘动的窗帘甚至家长的靠近干扰；摄像头知道“谁在那里”，但看不见心率。

[XIAO ESP32C6] ──(MQTT)──► [Orchestrator: Device Adapter] ◄──(ISAPI API)── [Hikvision Camera]
                                     │                                      (RTSP 流)
                                     ▼                                         │
[Orchestrator: Rule Engine] ◄────────────────────────────────────────────────── [NVR 视觉推理]

实战场景示例：雷达触发了“呼吸异常/呼吸停止”告警

    雷达通过 MQTT 发送 "abnormal_event": "apnea" (呼吸暂停)。
    Mac 上的规则引擎收到该信号，并不立即向手机发红色全屏告警。
    规则引擎立即向 NVR 模块请求当前的视觉推断状态。
    决策分叉：
        情况A：摄像头 AI 识别出此时“家长正在床边换尿布”（导致雷达心率检测丢失）。→ 拦截告警，作为日志记录。
        情况B：摄像头 AI 识别出此时“婴儿床内无人”。→ 拦截告警，标记为“宝宝离床雷达空发”。
        情况C：摄像头 AI 确认“宝宝在床内”，且检测到了“俯卧姿态候选（趴睡）”。→ **双重确认高危！触发 红色紧急全屏告警！**向父母手机 FCM 推送。

## 7. 多端同步方案

### 7.1 选型

选择：

> **PowerSync + PostgreSQL（Mac）+ SQLite（安卓手机）**

### 7.2 选型理由

- 适合本地优先、离线优先应用。
- 手机端可写本地 SQLite。
- 网络恢复后自动同步。
- Mac 端 PostgreSQL 作为权威源。
- 支持自托管，符合家庭私有化部署。
- 比自研同步省一套后端。
- 比 CouchDB / PouchDB 更适合关系型事件、统计、趋势分析。
- 比 WatermelonDB 少写自定义同步后端。

### 7.3 同步规则

每条记录必须包含：

```json
{
  "event_id": "uuid",
  "baby_id": "uuid",
  "family_id": "uuid",
  "user_id": "uuid",
  "device_id": "android_xxx",
  "event_type": "feeding|diaper|sleep|temperature|medication|supplement|symptom|media|sensor|device",
  "client_created_at": "timestamp",
  "server_received_at": "timestamp",
  "payload": {},
  "source": "manual|voice_text|camera|sensor|ai|system",
  "confidence": 0.0,
  "is_deleted": false,
  "correction_of": null
}
```

### 7.4 离线要求

- 手机离线时仍可完整记录。
- 离线记录写入本地 SQLite，并标记 pending_sync。
- 网络恢复后自动补传。
- Mac / PostgreSQL 作为权威源合并。
- 首页显示同步状态。
- 每条记录显示记录人。
- 不允许因同步失败丢记录。

### 7.5 冲突处理

| 冲突类型 | 处理方式 |
|---|---|
| 5 分钟内疑似重复喂奶 | 不自动删除，UI 软提示“疑似重复” |
| 两人同时编辑同一事件 | 保留版本，最后编辑为当前版本 |
| 离线期间重复记录 | 上线后合并提示 |
| 撤销记录 | 软删除，不物理删除，保留审计 |
| 图片 / 视频冲突 | 按 asset_id 独立保存 |
| 医疗 / 系统规则冲突 | Admin 二次确认，记录变更人、时间和版本 |

## 9. 长期记忆架构

长期记忆分五层，避免全部塞入向量库。

| 层 | 名称 | 内容 | 存储 | 用途 |
|---|---|---|---|---|
| M1 | 硬事实记忆 | 出生日期、胎龄、是否早产、出生体重、当前体重、过敏史、已接种疫苗、已知疾病 | 关系型 DB | 不允许 LLM 猜测 |
| M2 | 家庭偏好记忆 | 安抚奶嘴、按需喂养、夜间谁先响应、相册自动入库、常用医院、摄像头语音提醒 | 结构化 | 注入上下文 |
| M3 | 行为基线记忆 | 平均喂奶间隔、常见夜醒时段、日均湿尿布、常见入睡时长、常见哭闹前因 | 结构化 + 派生 | 趋势与预警 |
| M4 | 短期上下文记忆 | 近 72h 是否发热、接种、腹泻、奶量下降、睡眠碎片化 | 派生状态 | 临时推理 |
| M5 | 纠错记忆 | 图片误判、摄像头夜间误报、告警误报、药品浓度更正 | 结构化 + 少量向量 | 自适应调阈 |

健康类回答前，Orchestrator 必须自动注入：

- 宝宝日龄
- 当前体重
- 体重百分位
- 近期相关记录
- 家庭规则
- 过敏史
- 最近 72h 症状 / 用药 / 接种记录
- 相关规则版本

这是本系统区别于通用问答机器人的关键。

## 10. Agent 与 AI 架构

### 10.1 总体原则

本系统不采用“儿科专家 Agent / 行为专家 Agent / 新生儿专家 Agent”横向堆叠方式，而采用分层架构和收敛的 Copilot 体系。

### 10.2 Orchestrator 编排器

职责：

- 判断用户意图：
  - 记录
  - 提问
  - 求助
  - 配置
  - 告警确认
- 决定调用本地模型或云端模型。
- 注入宝宝上下文和长期记忆。
- 调用规则引擎。
- 调用领域 Copilot。
- 拦截危险输出。
- 输出可追溯建议。
- 生成轻确认卡片。
- 对任何医疗 / 用药建议绑定证据链。

### 10.3 剂量拦截器

Orchestrator 内置剂量拦截器。

规则：

- 任何 LLM 自由输出中包含具体药量数字，如 mg、ml、滴，必须拦截。
- 被拦截内容替换为：

> “具体剂量需由医生 / 药师确认，系统仅可在医生已授权且药品浓度、体重、月龄完整时，通过规则引擎进行用药执行校验。”

- 剂量只能由 Rule Engine 产出。
- LLM 只负责解释规则和风险，不负责自由计算或建议剂量。

### 10.4 领域 Copilot

| Copilot | 职责 | 安全等级 |
|---|---|---|
| Logger Copilot | 自然语言 / 语音文本转结构化事件；补录；去重；轻确认 | 低 |
| Health Triage Copilot | 症状分诊、风险等级、危险信号、家庭观察建议、就医建议、就诊摘要 | 高，需安全审查 |
| Proactive Copilot | 喂奶提醒、哄睡提醒/唤醒提醒、补剂、疫苗、体检、发育观察点、猛长期预告、趋势预警、晨报 | 低，规则为主 |
| Sleep Session Copilot | 睡眠会话开始 / 结束、夜醒检测、趴睡检测、遮脸检测、会话摘要 | 中，影子模式优先 |

### 11.6 睡眠会话，P0 / P1

#### 11.6.1 定义

睡眠会话是 摄像头 & 毫米波雷达 & Mac 服务端编排器主动开启或用户主动开启的一段监测时间，通常用于：

- 夜间睡眠
- 白天小睡
- 宝宝独自在婴儿床时

#### 11.6.2 会话状态

not_started
active
paused
ended

#### 11.6.3 会话能力

- 记录入睡时间。
- 记录醒来时间。
- 检测夜醒。
- 检测持续趴睡。
- 检测遮脸 / 被褥覆盖。
- 检测床区无人。
- 生成睡眠摘要。
- 显示 mmWave 状态。
- 保存红 / 橙告警事件片段。

#### 11.6.4 夜醒提醒

触发条件：

睡眠会话 active
AND 床区检测到持续大动作 / 坐起 / 睁眼 / 哭声候选
AND 持续时间 > 90 秒
AND 当前时间处于夜间提醒窗口
AND 过去 10 分钟未发过同类提醒

提醒等级：

- 默认黄色。
- 伴随哭声 / 持续动作可升级橙色。
- 不作为红色医疗告警。

#### 11.6.5 趴睡提醒

触发条件：

睡眠会话 active
AND 姿态 = prone / suspected_prone
AND 置信度 > 0.85
AND 连续持续 > 60 秒
AND 最近 5 分钟未提醒

提醒等级：

| 月龄 | 等级 |
|---|---|
| 0～3 月 | 橙色 |
| 3～6 月 | 黄色 / 橙色，可配置 |
| 伴随遮脸 | 红色，需多信号高置信 |

#### 11.6.6 护栏

- 仅睡眠会话内分析。
- 非睡眠会话仅定时抓拍。
- 上线前先跑 7 晚影子模式，只记录不打扰。
- 误报率未达标前不开强提醒。
- 摄像头分析不做生命体征判断。
- 摄像头不做呼吸频率监测。
- 床区 ROI 由用户手动框定。
- 视频默认只存事件片段，前 15 秒 / 后 30 秒。
- 原始流默认留在摄像头 microSD，Mac 只存索引和关键片段。
- 趴睡 / 遮脸等高风险提醒优先使用多信号融合，不依赖单一摄像头判断。

### 11.7 摄像头行为分析

### 11.11 用药安全，P0 基础 / V1 完整

#### 11.11.1 核心定位

系统不主动建议“喂几毫升”。

用药安全模块服务两个场景：

1. 输出该症状 / 月龄下的处理原则、危险信号、何时就医。
2. 医生开药后的执行器：
   - 父母输入医生开的剂量 / 频次 / 药品浓度。
   - 系统负责定时提醒。
   - 记录已喂。
   - 防重复给药。
   - 检查间隔。
   - 检查 24h 上限。
   - 展示计算链路。

#### 11.11.2 必须输入

- 宝宝月龄。
- 最新体重。
- 药品名称。
- 药品浓度。
- 上次给药时间。
- 医生是否已授权。
- 当前症状。
- 体温测量方式。

#### 11.11.3 规则流程

选择药物
  ↓
校验年龄
  ↓
校验体重是否过期
  ↓
确认药品浓度 / 规格
  ↓
检查禁忌
  ↓
规则引擎计算 mg
  ↓
换算 ml
  ↓
检查给药间隔
  ↓
检查 24h 总量
  ↓
展示计算链路
  ↓
父母二次确认
  ↓
写入用药时间线

#### 11.11.4 硬性限制

| 情况 | 系统行为 |
|---|---|
| 未知体重 | 不输出剂量 |
| 未知浓度 | 不输出 ml |
| 体重记录过旧 | 要求更新体重 |
| 布洛芬 <6 月龄 | 默认锁定，仅允许“医生已明确要求”模式 |
| 3 月龄以下发热 ≥38°C | 触发红色分诊，不优先给药 |
| 24h 已接近上限 | 阻止重复给药 |
| 用户要求 LLM 估算剂量 | 拦截 |
| LLM 输出 mg / ml / 滴 | 拦截 |

### 11.13 成长曲线，P0

记录字段：

- 体重。
- 身长 / 身高。
- 头围。

分析：

- WHO 百分位。
- 0～5 岁标准。
- 按性别区分。
- 近 30 天趋势。
- 与出生数据对比。
- 百分位异常变化提醒。

限制：

- 只做趋势提醒。
- 不基于单次记录诊断营养不良或发育异常。

### 11.14 黄疸照片日记，P0 基础 / V1 趋势

定位：

只做：

- 照片记录。
- 拍摄规范提醒。
- 同一位置趋势对比。
- 线下测胆红素提醒。
- 标记是否已线下测胆红素。

不做：

- 胆红素数值预测。
- 黄疸医学诊断。
- 光疗阈值判断。

拍摄规范提醒：

- 尽量自然光。
- 同一房间。
- 同一角度。
- 同一白色背景。
- 避免美颜 / 滤镜。
- 记录拍摄时间。
- 记录拍摄部位 / 位置。
- 标记是否已线下测胆红素。

### 11.15 发育里程碑，V2 / V3

形式：

- 到龄提醒。
- 观察清单。
- 父母打卡。
- 照片 / 视频留证。
- 活动建议。

限制：

- 不做 AI 视频自动识别。
- 不做发育诊断。
- 采用 CDC / Kinedu 风格清单式体验。

### 11.16 家庭知识库，P0

内容：

- 家庭规则。
- 医疗偏好。
- 照护偏好。
- 宝宝特征。
- 常用医院 / 儿保机构。
- 夜间响应规则。
- 是否使用安抚奶嘴。
- 是否按需喂养。
- 是否允许自动保存相册。
- 是否接受摄像头语音提醒。

要求：

- 必须结构化，不只是长文本。
- 所有 Copilot 调用前可读取。
- 重要规则变更需记录变更人和时间。

### 11.17 母亲产后健康，P0 数据预留 / V2 功能

## 12. 风险预警体系

### 12.1 告警等级

| 等级 | 名称 | 触发示例 | 送达 | 原则 |
|---|---|---|---|---|
| 灰色 | 系统告警 | 摄像头离线、Mac 服务挂、同步未完成、SD 卡满、mmWave 离线 | App 提示 + 摘要 | 保证系统可信 |
| 蓝色 | 常规提醒 | 喂奶提醒、哄睡提醒/唤醒提醒、疫苗、补剂、体检、里程碑观察点、猛长期预告 | App 推送，可定时 | 主动价值最高 |
| 黄色 | 关注趋势 | 睡眠显著碎片化、单日湿尿布偏少、夜醒提醒 | App 推送，非强打扰 | 必须趋势 / 会话条件 |
| 橙色 | 尽快处理 | 连续奶量下降且尿布减少、呕吐腹泻伴脱水风险、黄疸趋势加重、单独趴睡超时 | App 推送 + 可声音 | 24h 内联系医生 |
| 红色 | 立即处理 | 3 月龄以下发热达红线、明显呼吸困难、反应差、惊厥、遮脸多信号高置信 | 全通道强提醒 | 高特异，宁缺毋滥 |

### 12.2 红色告警原则

红色告警必须：

- 高特异。
- 有明确危险信号或多信号一致证据。
- 能追溯触发依据。
- 不由单一毫米波异常独立触发。
- 不由摄像头单帧判断触发。
- 用户输入危险症状可直接触发。
- 多信号高置信遮脸可触发。

### 12.3 抗告警疲劳机制

- 黄色 / 橙色告警默认需“连续 N 天”或“偏离 X%”双条件，阈值可调。
- 趋势类避免单点触发。
- 影像 / 雷达类高风险提示默认降一级，除非睡眠会话内多信号一致。
- 同类黄色告警 24h 内不重复。
- 非红 / 橙告警每天合并为一条晨报摘要。
- 每条告警支持反馈：
  - 有用
  - 误报
  - 太敏感
  - 已知道
  - 忽略
- 反馈写入 M5 纠错记忆，用于自动调阈。

## 13. 紧急告警送达链路

### 13.1 多通道送达

红 / 橙告警触发后：

触发红/橙告警
  ├─ 通道1：双亲安卓 FCM 高优先级推送
  │        仅传 alert_id / level / type，详情回连 Mac 获取
  ├─ 通道2：Mac 客厅扬声器语音告警
  └─ 通道3：App 内全屏告警 + 持续震动响铃
        ↓
任一人点击“我已知晓”
        ↓
全部停止
        ↓
记录确认人 / 时间 / 设备

### 13.2 升级策略

| 时间 | 行为 |
|---|---|
| 0 秒 | 双亲手机同时推送 |
| 60 秒未确认 | Mac 重复语音 |
| 90 秒未确认 | 手机再次高优先级提醒，提高音量 / 强震动 |
| 任一人确认 | 全部停止，记录确认人 |

### 13.3 安卓实现要求

必须支持：

- 高优先级通知通道。
- IMPORTANCE_HIGH。
- 全屏 Intent。
- 自定义声音。
- 自定义震动。
- 锁屏弹出。
- 本地通知兜底。
- 后台同步。
- 电池白名单引导。
- 自启动白名单引导。
- FCM 仅承载触发信号，不携带隐私详情。

### 13.4 安卓高风险技术点

必须生产前优先预研：

- Android 14+ 全屏 Intent 权限限制。
- USE_FULL_SCREEN_INTENT 权限申请。
- canUseFullScreenIntent() 检查。
- ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT 授权引导。
- Doze 模式下定时提醒延迟。
- setExactAndAllowWhileIdle() 的限制。
- 国产 ROM 后台杀进程问题。
- 电池白名单 / 自启动白名单配置流程。
- 手机离线或进程被杀时，Mac 扬声器必须作为本地兜底链路。

## 15. 隐私与安全

### 15.1 数据隐私策略

| 数据 | 默认策略 |
|---|---|
| 视频 | 不上传第三方云，本地 microSD / Mac 存储 |
| 图片 | 本地存储，文件加密 |
| 音频 | 本地处理或转文本后删除 |
| 医疗记录 | 本地加密 |
| 推送内容 | 仅 alert_id / level / type，不发详情 |
| 云端 LLM | 仅脱敏文本 |
| 原始视频流 | 默认不离开家庭局域网 |
| MD/PDF 导出 | 用户主动生成 |

### 15.2 权限控制

| 角色 | 权限 |
|---|---|
| Admin | 全部权限 |
| Caregiver | 记录、查看部分状态，不可改医疗 / 系统规则 |
| Viewer | 查看摘要和相册 |
| System | 自动写入设备与分析事件 |

### 15.3 安全措施

- 家庭局域网访问默认开启。
- 远程访问推荐 Tailscale / WireGuard。
- 数据库定期备份到 NAS。
- 图片 / 视频文件本地加密。
- 操作日志不可删除。
- 医疗 / 用药规则变更需记录版本。
- 重要规则变更需记录变更人和时间。
- 摄像头厂商云必须关闭并验证。
- 云端 LLM 仅可接收脱敏文本。
- 推送详情必须回连 Mac 获取。

### 15.4 审计日志

- 谁创建记录。
- 谁编辑记录。
- 谁撤销记录。

### 18.3 P0 验收标准

#### 同步验收

- 安卓手机离线记录 10 条，上线后全部同步。
- 父母两台手机均能看到对方记录。
- 撤销记录在两端同步。
- Mac 重启后数据不丢。
- 首页展示同步状态。
- 每条记录显示记录人。

#### 告警验收

- 红色测试告警同时触达两部安卓手机。
- Mac 扬声器响。
- 摄像头扬声器响。
- App 全屏告警弹出。
- 一人确认后全部停止。
- 未确认 90 秒后能升级。
- FCM 推送不携带隐私详情。

#### 摄像头验收

- 卧室摄像头夜间画面清晰。
- Mac 稳定拉流 8 小时。
- 睡眠会话可保存事件截图。
- 摄像头离线 60 秒内触发灰色告警。
- 已验证厂商云关闭且流量不出局域网。

#### 趴睡 / 夜醒验收

- 先跑 7 晚影子模式。
- 误报达标前不开强提醒。
- 趴睡提醒未稳定前不得作为红色告警。
- 摄像头不得做生命体征判断。

## 21. 关键风险与应对

### 21.1 摄像头误报风险

风险：

- 红外夜视不保证姿态识别准确。
- 被子、睡袋、角度、遮挡都会影响判断。
- 单帧判断容易误报。

应对：

- 只在睡眠会话内分析。
- 引入床区 ROI。
- 设置持续时间阈值。
- 先影子模式。
- 高风险告警保存证据截图。
- 用户反馈后调整阈值。
- 多信号一致才升级高风险提醒。

### 21.2 毫米波设备误用风险

风险：

- 用户可能误以为它能预防 SIDS。
- 数据准确性与开放性不确定。

应对：

- 明确标注“辅助监测，不替代成人照护”。
- 不单独触发医疗红色告警。
- 与摄像头、声音、父母输入联合判断。
- P0 只预留，V2 正式接入。

### 21.3 用药风险

风险：

- 浓度错误。
- 体重错误。
- 月龄禁忌。
- 重复给药。
- LLM 自由输出剂量。

应对：

- 浓度强校验。
- 体重过期拦截。
- 6 月龄以下布洛芬锁定。
- 24h 总量检查。
- 医生授权模式。
- LLM 剂量拦截器。
- 展示完整计算链路。
- 父母二次确认。

### 21.4 安卓告警可靠性风险

风险：

- Android 14+ 全屏 Intent 权限限制。
- Doze 模式延迟。
- 国产 ROM 杀后台。
- FCM 延迟。
- 手机离线。

应对：

- 生产前优先预研。
- 引导开启全屏 Intent 权限。
- 引导加入电池白名单 / 自启动白名单。
- 使用 Mac 扬声器兜底。
- 使用摄像头扬声器兜底。
- 红 / 橙告警多通道升级。
- FCM 仅做触发，不承载详情。

### 21.5 个人开发时间风险

风险：

- 1 个月内功能过多。
- 出生后严重睡眠剥夺，无法频繁 debug。

应对：

- P0 聚焦高频、可靠、零误判风险。
- AI 强判断类后置。
- 趴睡 / 遮脸先影子模式。
- 哭声分类后置。
- 自动里程碑识别后置。
- 医疗复杂能力后置。
- 医院医生推荐移交独立项目。

## 23. 最终产品结论

AI Parenting Copilot 不是“什么都懂的 AI 育儿大师”，而是一个长期运行在家里、以宝宝状态为中心的家庭育儿操作系统。

它能让父母在凌晨 2 点单手暗屏完成记录；让两个人始终看到同一条时间线；每天准时提醒补 VitD；在该喂食、该哄睡/唤醒、该打疫苗、该体检、猛长期来临时主动预告；在宝宝夜醒、趴睡、遮脸或设备离线时提醒；在发热和用药时用规则引擎守住安全边界；同时照顾到妈妈的产后恢复；并随着数据积累越来越懂“我家宝宝”。

本产品的核心取舍是：

- 记录、同步、提醒、告警是生产前必须完成的可靠地基。
- 安卓手机是主端，Mac 是家庭服务端。
- 多端同步选 PowerSync，不自研。
- 视频、图片、音频默认不出家门。
- 云端 LLM 只接收脱敏文本。
- 摄像头睡眠安全分析保留，但以睡眠会话、影子模式、多信号融合和置信阈值工程化。
- 呼吸 / 心率交给毫米波设备作为辅助安心层，但不包装成医疗监护。
- 用药剂量只做医生开药后的安全执行器，不让 LLM 开药。
- 黄疸只做照片趋势，不做胆红素预测。
- 哭声分类和自动里程碑识别后置。
- 母亲产后健康、猛长期预告、夜间模式、医生 PDF 是高价值补强项。
- 先把高频、可靠、安全的系统搭起来，再逐步增加 AI 能力。
